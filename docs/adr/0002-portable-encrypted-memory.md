# Synchronise portable events instead of a live database

Each trusted device will keep its own local working database, while signed, encrypted, append-only Luna records travel in a reserved area beside the cabinet. We rejected synchronising a live database because consumer cloud drives can copy partial writes and create conflicting versions; the event approach costs more merge engineering but preserves user-owned portability and makes conflicts explicit.

Each record is encrypted with the Household key and signed with the originating Trusted Device's separate authorisation key. Import verifies the device signature, activation epoch, optional revocation sequence/digest cutoff and event chain before decrypting or changing local state. Duplicate delivery is idempotent; modified, post-revocation or replay-invalid records are rejected. Concurrent mutable facts retain both valid records and create a resolvable Portable Memory Conflict rather than applying last-write-wins. Resolutions are portable signed events too; concurrent opposing resolutions create another explicit conflict instead of making rebuild order-dependent.

The portable schema is deliberately typed around durable domain facts. State, authority, provider, consent purpose and outcome values are closed enums, while references must use an allowlisted owning-domain kind plus a canonical UUID. A Filing Rule carries the complete bounded matching scope and Cabinet Destination needed to rebuild learned behaviour. A Consent Grant carries its exact model, capability, disclosed fields, Member reference and lifecycle timestamps. A reusable grant also carries its future evidence scope; a one-time grant names its Document through a canonical Portable Reference rather than a device-local arrival ID. Common disclosure fields are closed variants; additional field names and reusable scope field/value evidence are bounded and secret-shape checked so an imported reusable grant can enforce the same scope without carrying provider output or credentials. One-time grants remain portable historical authority but are not installed as executable Consent on another device. The schema has no field for credentials, private keys, derived Conversation Prompts, transient Conversation Orchestration, hidden reasoning or raw Intelligence Provider output.

Owning stores produce the portable facts. Successful Conversation, Filing Rule, duplicate and Cloud Assistance commands capture their resulting durable facts automatically; credential-vault operations are not an input to this adapter. The adapter does not infer an Authority Grant from a Filing Rule: authority becomes portable only when an explicit owning authority source produces it. Keep local remains a direction and outcome rather than being fabricated as a denied Consent Grant. On import, Luna hydrates Filing Rules and reusable Consent Grants back into their owning stores, rebuilds protected relationship and History projections in the Conversation owner, and withholds conflicted rules from automation until resolution. A recovered rule and a recovered reusable Consent Grant are therefore executable behaviour, not display-only portable projections. Filing-rule changes, Cloud Assistance completion, Keep local, retryable provider failure and candidate disposition retain distinct immutable outcomes; provider execution is authorised by Consent until a member accepts or corrects its candidate.

Recording is local-first. Luna commits the encrypted Portable Memory Record and its local projection before attempting Cabinet delivery. If the remembered Cabinet is unavailable, the exact signed record remains pending in that device's local database; the next synchronisation delivers it without reconstructing or re-signing the fact. Synchronisation distinguishes an unavailable Cabinet from an available Cabinet with no records.

The Account Service coordinates only public verification metadata: each device's authorization public key, activation epoch and, after revocation, the final accepted key epoch, sequence and digest. The revocation and cutoff update is atomic. Record contents and Household keys remain unavailable to the service.

Each import transaction advances the typed local projections for current Filing Rules, Document relationships, Authority Grants and Consent Grants and appends Member Direction, execution outcomes and Audit Events to local History. A mutable subject with an unresolved conflict—including an unresolved conflict between competing resolutions—is withheld from the current projection until a portable resolution selects it.
